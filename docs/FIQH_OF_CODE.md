## 4. Cross-Language Merkle Verification Parity (`Solidity` ↔ `Python` ↔ `Odoo` ↔ `TypeScript`)

To guarantee **bit-for-bit audit reproducibility** between Odoo 20.0, Python CLI tools, browser WebCrypto verification, and EVM smart contracts, all four runtimes implement the exact same Merkle algorithm:

1. **Canonical Leaf Preimage:** UTF-8 JSON serialized with `sort_keys=True` and `separators=(",", ":")`, scrubbed of all raw PII (`privacy_shield.py` / `merkle_stdlib.py`) and containing `wakif_commitment` (`"0x" + sha256("waqf:uupdp:v1:" + salt + ":" + normalized_id)`).
2. **Domain-Separated Leaf Hash (`0x00`):**
   - Solidity (`WaqfAuditRegistry.sol`): `sha256(abi.encodePacked(uint8(0x00), sha256(payload)))`
   - Python (`merkle.py` / `merkle_stdlib.py`): `hashlib.sha256(b"\x00" + hashlib.sha256(payload_bytes).digest()).digest()`
3. **Sorted-Pair Internal Node Hash (`0x01`):**
   - Solidity (`WaqfAuditRegistry.sol`): `if (computed <= sibling) sha256(abi.encodePacked(uint8(0x01), computed, sibling)) else sha256(abi.encodePacked(uint8(0x01), sibling, computed))`
   - Python (`merkle.py` / `merkle_stdlib.py`): `a, b = (left, right) if left <= right else (right, left); sha256(b"\x01" + a + b)`
4. **Odd-Node Promotion:** At any tree level of odd length $2k + 1$, the unpaired node at index $2k$ is promoted unchanged to the next level without sibling emission, exercised directly in the 5-leaf `CANONICAL_AUDIT_LEAVES` browser verifier (`apps/explorer/src/data/genesisData.ts`) and Genesis Epoch `2026-11` 10-leaf tree (`0x8847ae1a98d62b44dbbfe44900cce0620b7e13914d9bd509d3d694f8fb3921cc`).
